# AR Room Demo

Мобильный технический прототип для размещения интерьерных 3D-объектов и материалов в WebAR. В проекте нет авторизации, магазина, цен, серверной части или передачи кадров камеры на сервер.

## Что реализовано

- настоящий `immersive-ar` WebXR-сеанс с feature detection и hit-test по горизонтальной поверхности;
- лениво загружаемые GLB-модели дивана, кресла, стола, телевизора, окна и люстры;
- материалы стены и пола с повторяющимися текстурами;
- одновременное размещение нескольких элементов;
- выбор, перемещение по допустимой плоскости, pinch-масштабирование и вращение двумя пальцами;
- кнопки масштаба, поворота на 15°, дублирования, замены и удаления;
- сброс сцены с подтверждением;
- desktop-деморежим с виртуальной комнатой;
- fallback по загруженной фотографии, обрабатываемой только в браузере;
- экспорт PNG и системный Share API, когда браузер это поддерживает;
- понятная индикация поддержки устройства и сообщения об ошибках;
- мобильный интерфейс с safe-area и сенсорными областями не меньше 44 px.

## Технологический выбор

Использован Vite вместо Next.js: прототип полностью клиентский, backend и SSR не нужны, а Vite даёт маленькую статическую сборку и простой HTTPS-деплой. Рендеринг построен непосредственно на Three.js, чтобы жизненный цикл WebXR-сеанса, hit-test и освобождение GPU-ресурсов оставались явными. Zustand хранит только сериализуемое состояние сцены.

## Запуск

Требуется Node.js 20+.

```bash
pnpm install
pnpm generate:models
pnpm dev
```

Для проверки на телефоне сайт должен быть открыт по HTTPS (кроме `localhost`). Production-сборка:

```bash
pnpm build
pnpm preview
```

Переменные окружения не нужны.

## Устройства и ограничения

Полный AR предназначен для Android Chrome, устройства с ARCore и Google Play Services for AR. Реальная поддержка проверяется через `navigator.xr.isSessionSupported('immersive-ar')`; отсутствие WebXR никогда не маскируется под рабочий AR.

Safari на iPhone на момент реализации не предоставляет стандартный WebXR `immersive-ar` в обычном веб-сайте. На iPhone доступны desktop-демокомната и режим фотографии: пользователь делает или загружает кадр, размещает элементы и сохраняет композицию. Пространственного трекинга в этом fallback нет.

Текущие честные ограничения прототипа:

- WebXR hit-test автоматически находит горизонтальные поверхности; стена и потолок используют ручную точку относительно найденной поверхности;
- WebXR anchors и light estimation запрашиваются как optional, но MVP не зависит от их наличия;
- материалы представлены прямоугольными плоскостями с перспективно корректными UV Three.js, без автоматической сегментации стен и окклюзии реальной мебелью;
- снимок WebXR framebuffer зависит от политики конкретного браузера; при запрете показывается ошибка, в desktop/photo fallback экспорт работает;
- модели намеренно стилизованные и низкополигональные; это тест привязки и UX, не финальная визуализация;
- физическая проверка на конкретном ARCore-устройстве должна выполняться после HTTPS-деплоя.

## Ассеты и лицензии

Все GLB-модели созданы локальным генератором `scripts/generate-models.mjs` из простых оптимизированных примитивов. Точки привязки соответствуют типу размещения: низ для мебели, задняя поверхность для настенных элементов, верхняя точка для люстры. Текстуры SVG также созданы для этого проекта. Сторонних 3D-ассетов нет; лицензия описана в `public/models/LICENSE.md`.

## Проверки

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

Unit-тесты покрывают ограничения масштаба, добавление, замену, дублирование, удаление, очистку сцены и допустимость поверхности.
